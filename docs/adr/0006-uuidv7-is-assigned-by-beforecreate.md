# UUIDv7 primary keys are assigned by a BeforeCreate hook

Posts and Pages use UUIDv7 primary keys, generated by a `BeforeCreate` method on
each model rather than by pop.

This looks like ceremony that could be deleted, and it cannot. Pop hardcodes
`uuid.NewV4()` in `dialect_common.go` and applies it only when the ID is still
the zero UUID — there is no setting that asks for another version. Version 7 is
time-ordered, which is the entire reason for choosing it over v4: it keeps index
inserts local and makes rows sort by creation. `gofrs/uuid v4.4.0` already
provides `NewV7()` and is already a pop dependency, so nothing new is required.

`Migrator.exec` calls the callbacks before `Dialect.Create`, so the hook wins and
pop's v4 fallback never runs.

## Consequences

- Deleting the hook does not break anything visibly. Inserts keep working and
  silently become v4, and the ordering property is lost for every row written
  afterwards, with no error to notice. That silence is why this is written down.
- The hook belongs on the model, not on `Store`, so it covers `Create`, `Save`
  and `ValidateAndCreate` alike — including insert paths not yet written.
